Patterns · 24 · Architecture

Three-Tier Drill-Down

Every screen maps to one of three tiers. Users always move summary → operational → detail — never sideways into ambiguity.

Tier 1 · Summary
Orientation
"What needs attention?" — KPI cards, dominant metric, delta. Answers in 2 seconds.
Job: signal, not resolve.
Tier 2 · Operational
Context
"Which ones, in what order?" — queues, comparison, trend modules. Filter pre-applied.
Job: scope the work.
Tier 3 · Detail
Resolution
Drawer (inspect-and-return) or full page (task-switch). Drawer first.
Rule: page only when committing.
Patterns · 25

Progressive Disclosure

Four containers, four roles. Choose by user intent — not by convenience.

Tabs
Peer Categories
Switch between equal-weight views of the same dataset.
Use when: 2–5 peer filters
Accordion
Optional Detail
Secondary info most users skip. Collapsed by default.
Use when: detail is opt-in
Drawer
Inspect & Return
Peek at a record without losing list context. Esc, backdrop, X.
Use when: user will inspect >1
Modal
Interrupt Worthy
Confirmation, destructive action, required form. Narrow only.
Use when: can't proceed without
Patterns · 26

The Six Data States

Every module must handle all six. Missing coverage is a build blocker — not an edge-case.

01 · Loading
Skeleton
Shimmering bars at element shapes. Never spinners over content.
02 · Empty
Wayfinder + Copy
Quiet celebration when empty = success. Never icon-spam.
03 · Error
Cause + Retry
Name what failed. Offer a retry CTA. Avoid stack traces.
04 · Partial
Module Offline
Mark only the failed module — don't blank the whole page.
05 · Stale
Show Age
"Last updated 14 min ago" beats invisible cache lies.
06 · Permission
Request Access
Explain the role gate. Provide a one-click request action.
End
