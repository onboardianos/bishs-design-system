D3

What goes in an element's ID

BOS v0 put the breakpoint and grid position inside the ID, so the same button changed identity when you resized. v2 keeps one stable ID and moves structure into attributes. The remaining choice is the ID prefix.

BOS v0: ID changes per widthBreaks RF01
1440px SM-FLOOR-001.dt/S99/btn-commit-checkin@c9-12r93-99 390px SM-FLOOR-001.ph/S99/btn-commit-checkin@c1-4r104-110
Two different IDs for one button. The manifest, the align stage and the spec board all lose track of it.
v2 (a) Class as prefixRecommended
data-spec-id="btn-commit-check-in" data-bos-class="commit" data-bos-section="S99" data-bos-grid="c9-12r93-99" ← live, not ID
One ID at every width. The class is readable in the ID itself, and spoken-label matching still works ("check in").
v2 (b) Keep v1 prefixes onlyLess legible
data-spec-id="btn-check-in" data-bos-class="commit"
Shorter IDs, but you can't tell COMMIT from ACTION without reading a second attribute.
