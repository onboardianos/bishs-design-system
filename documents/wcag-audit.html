01

Text Color Contrast

The brand cream and pure white pass comfortably everywhere. The failures cluster in the muted/subtle grays and in the gold accent when it carries text — and they get worse as surfaces lighten from page → card → raised.

Critical
White text on the primary (gold) button fails
SC 1.4.3 Contrast (Minimum) · Button.jsx primary variant

The primary CTA is #FFFFFF on #8B752E — your highest-traffic action. It lands at 4.48:1, just under the 4.5 floor, and the hover state #B89E4A drops it to 2.62:1 — i.e. the button becomes less legible exactly when the user interacts with it.

Switch primary-button text to near-black #020000. Black-on-gold is core brand DNA, passes at rest and hover, and needs no palette change. (Alternatively darken the button gold, but the text swap is cleaner.)

--text-muted #7A7D76 passes on the page (5.0:1) but degrades as surfaces lift. It's used for input helper text on #111E1E (4.1:1), row meta on cards (3.4:1), and content on raised panels (3.0:1) — all under 4.5 for the small sizes it's paired with.

--text-light-muted fails on light surfaces

--text-light-muted #9C9C94 on the light page (#F7F6F1) is only 2.56:1, and barely better on white cards (2.66:1). It's too light for any text that must be read. The tier above it, --text-light-tertiary #6B6B63, is fine (≈5:1).

Recommended fix

Use --accent-gold-hi for overlines and any gold text on card/raised surfaces; reserve base --accent-gold for borders & large fills. Bump the overline floor from 10px → 11px.

Moderate
--text-subtle is sub-readable everywhere
SC 1.4.3 · verify it is only used decoratively

--text-subtle #4A4D46 tops out at 2.44:1 (on page) and falls to ~1.6:1 on cards. That's fine only if it's strictly disabled-state or non-informational dividers/placeholder glyphs (which WCAG exempts). If any real content uses it, that content is effectively invisible to low-vision users.

Recommended fix

Audit usages and document --text-subtle as disabled/decorative-only in the README. For any informational text currently using it, promote to (the new) --text-muted.

02

Semantic Status Colors

The Material-3 status colors read well as text/icons on the dark page, but break in two common patterns: white text on a saturated fill, and status text placed on raised card surfaces.

Critical
White text on success / warning / info fills fails
SC 1.4.3 · solid status badges & buttons

White-on-fill only clears AA for danger (and only barely, 4.51:1). The rest are well short — warning is unusable with white text.

Recommended fix

Codify the rule: white text only on the *-dark variant of each status color; warning always takes near-black text (it's a yellow). You already ship the -dark tokens — this is a usage rule, not a new color.

Moderate
Status text on card/raised surfaces dips below 4.5
SC 1.4.3 · colored status labels on dark cards

As text on the dark page the base status colors pass (danger 4.6:1, info 5.0:1, success 6.1:1). One surface up, on a card, they fall to 3.1–4.1:1. The dark-theme badge pattern (12% tinted background + colored text) inherits the same problem unless the text tone is lightened.

Recommended fix

Add lighter "on-dark" status text tints (e.g. success #51CF66, danger #FF8787, info #74C0FC, warning #FFD43B) for use on card/raised surfaces and inside tinted badges. The light theme already does this correctly with its -light/-dark pairing.

03

Non-Text Contrast & Use of Color

WCAG 2.2 requires UI component boundaries and meaningful graphics to hit 3:1 (1.4.11), and information must never be carried by color alone (1.4.1).

Critical
Links are distinguished by color only
SC 1.4.1 Use of Color · global a styling

Links render as --accent-gold-hi with underline only on hover. Against cream body text the link/text color contrast is just 1.92:1 — below the 3:1 that 1.4.1 requires when color is the only differentiator. A user who can't perceive the gold/cream difference can't find links in running text.

Recommended fix

Give in-text links a persistent underline (remove the hover-only rule), or add another non-color cue (weight/icon). Standalone nav/button links that aren't embedded in prose are exempt.

Serious
Input borders & hairlines fall below 3:1
SC 1.4.11 Non-text Contrast · Input.jsx, --border-ghost/mid/light

The resting input border is rgba(255,255,255,0.13) (≈#303B3B composited) sitting on a card — roughly 1.4:1 against the surrounding surface, so the field's edge is barely perceptible. The dark input fill (#111E1E) vs the card it sits on is only ~1.2:1, so the fill doesn't rescue it either. Light-theme borders (rgba(0,0,0,0.06–0.08)) are similarly faint on white. The focus ring (gold-hi) is fine — it's the resting state that's invisible.

Recommended fix

Introduce a dedicated --border-input that hits 3:1 against its surface — roughly rgba(255,255,255,0.30) on dark and #949494 on light. Decorative hairlines (--border-ghost) can stay faint, but any border that is the only indicator of an interactive control must meet 3:1.

04

Typography & Target Size

These aren't hard contrast failures but they degrade readability and tap accuracy — and one (target size) is a WCAG 2.2 AA criterion.

Moderate
Sub-11px type, especially uppercase condensed
Readability · WCAG 1.4.4 Resize Text (best practice)

The scale bottoms out at --fs-label-sm 10px and the queue module ships 9.5px uppercase badge text and 10px overlines. Uppercase Barlow Condensed with wide letter-spacing at 9–10px is hard to read for everyone and punishing for low-vision users. Numeric data in 11px mono (VINs, due times) is the workhorse and should be the floor, not below it.

Recommended fix

Set an 11px floor for any persistent text (12px preferred for body/meta). Raise badge text 9.5px → 11px and overlines 10px → 11px. Keep 10px strictly for non-essential decorative labels, if at all.

Moderate
Filter chips fall under the 24px target minimum
SC 2.5.8 Target Size (Minimum) · queue filter chips

The pill filter chips ("All · 7", "Overdue · 2") render at ~20–22px tall with 3px vertical padding — under the 24×24px minimum WCAG 2.2 introduced. The sm button (32px) and comfortable targets (48px) are fine; compact-mode 36px is fine. The chips are the outlier.

Recommended fix

Pad interactive chips to ≥24px tall (28–32px recommended for comfortable density). Non-interactive badges are exempt.

06

Sequencing

If you want to ship in waves:

  • Wave 1 — single-line swaps, ship today. Primary-button text → black; overline → gold-hi; persistent link underline; white-text-on-*-dark rule for status fills. Zero layout risk.
  • Wave 2 — token revalues. Lighten --text-muted, darken --text-light-muted, add --border-input and on-dark status tints. Re-snapshot the kit after.
  • Wave 3 — type & targets. Raise the size floor to 11px, grow chip targets to ≥24px, document --text-subtle as decorative-only.
